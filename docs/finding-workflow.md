# 发现、报告与复测

Lode 把“发现”“复测”“报告”分开保存。发现来自任务的 SARIF 和黑板；报告保存到对应任务的 `reports/<finding_id>.md`；复测记录写入 state 目录的 `finding-retests.jsonl`，每次复测都有稳定 ID、来源、状态和证据。

自动复测只有在本地留有以下材料时才会入队：原始单请求、原任务 `scope.json`、允许的方法和请求体声明、以及能够比较当前结果的响应状态或标记。它会重放原始请求，经 scope、操作语义、预算、限速和审计链；不会根据发现标题猜 URL，也不会把首页 GET 当成复测。

POST 是否能复测取决于语义。明确的搜索、查询、列表、查找、计数路由，或不含 mutation/subscription 的 GraphQL query，可以在 scope 声明允许 POST 和 body 时复测。删除、清空、截断、丢弃、移除、更新等语义无论出现在 GET、POST、方法覆盖参数、JSON、表单或嵌套字段里都被拒绝；PUT/PATCH 和 DELETE 也不会通过复测入口。上传、爆破、凭据使用、数据外带和全量扫描不会由复测按钮启动。

自动结果只有 `reproduced` 或 `inconclusive`，不会自动写 `fixed`。`fixed` 需要人工提交三份不同的本地证据：原始条件仍可复现、当前条件不再复现、正常对照通过；服务端会读取文件并记录 SHA-256 与大小。复测结论不会自动关闭原发现，报告中的结论和处置仍由操作员决定。

Console 的发现页支持搜索、严重度/复测状态筛选、最多 20 条批量复测、单条报告编辑与下载、自动复测轮询和人工结果录入。批量入口只创建有界的独立复测任务，不合并 scope，也不会绕过单条复测的安全检查。
