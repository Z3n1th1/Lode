# ByteSRC 打法（V6 / 测试红线 / 暂不收取）

来源：操作员提供的《安全报告处置规则 V6.0》正文（OCR 有噪点，已按公开公告校对）。
清单不定期更新。以 `src.bytedance.com` / 飞书最新公告为准。

安全测试的目的是证明漏洞存在、推动修复，不是利用漏洞、扩大影响。

命中下面「不收 / 暂停 / 仅高危」的资产或类型：**不要当 finding**，写 dead_end，原因写「ByteSRC 暂不收取」。

## 测试红线

1. 合法合规。
2. 禁止内网横向。
3. 禁止自动化扫描与拒绝服务。本场只做低频精确主机 GET/HEAD。
4. 禁止批量取数。越权 / 注入真实数据不超过 5 组。
5. 禁止深层渗透：禁止 WebShell、后门、**执行系统命令**、增删改、破坏性 Payload。最小无害 PoC。
6. 禁止下载、外传、留存源码 / 运营数据 / 用户资料 / 登录凭证。
7. 禁止自行深入验证凭据。拿到 AK/SK、kube-config、ServiceAccount：**直接提交**，审核验证影响。严禁自行深入业务。
8. 禁止超出授权范围。禁止测第三方服务、外部 API、CDN。禁止违法测试素材。
9. 禁止社工、钓鱼、近源、打扰真实用户。
10. 禁止逃避审计与瞒报。测试全程留痕。

敏感测试（反弹 shell、容器逃逸、文件上传等）必须提前报备，未报备不奖。翻凭据、增删改属于禁止测试，报告里写利用思路即可。

## 大模型产品（豆包 / 扣子 / 即梦等）

默认不收：

- 非信息安全漏洞导致的内容安全风险。
- 与模型提示、响应内容相关的问题：越狱 / DAN、输出恶意内容、幻觉成终端去「执行命令」。
- 非隐私数据泄露的 AI 服务风险（jailbreak、prompt leak）。
- 个人用户从 Coze 发布到豆包的智能体 / 插件（UGC 自身行为导致的信息泄露）。
- 沙箱里的代码执行 / 命令执行本身是产品功能。

例外才收：能造成额外、可直接验证的机密性 / 完整性 / 可用性影响；沙箱逃逸到宿主机 / 物理机、拿到有效敏感信息和权限、或证明打通字节内网。

恶意内容向产品帮助中心反馈，不要当 SRC 洞：豆包 → 设置 → 帮助和反馈；扣子 → feedback@coze.cn。

## 通用「忽略」范畴

- 与字节跳动（中国区）业务无关。
- 非字节（中国区）研发 / 运维的第三方：代维小程序、API、服务器、营销活动、外包系统、抖音电商 ISV。
- 报告过简、反复沟通仍无法复现。
- 内部已知：公开的 Jenkins 类通用洞、内部已发现、他人已先提交。
- 正在专项排查 / 专项治理期间暂不收取。
- 无法利用或无危害：恶作剧 CSRF、不影响他人的本地 DoS、Self-XSS、非敏感信息泄露（内网 IP、域名）、无法远程利用的 DLL 劫持、静态文件目录遍历。
- 和安全无关的 Bug：打开慢、样式乱。
- 只给理论、无成功率 / 未验证（例如只丢一个 dnslog 的「log4j」）。
- 用户名遍历、SPF 邮件伪造：不收取。
- 简单 DNS 日志型 SSRF：不收取。

## 本场优先（高危才报）

低危信息泄露、Self-XSS、用户名遍历、SPF、简单 DNSLog SSRF：**不当 finding**。本场只追：

1. **RCE 形状（第一优先）**：未授权管理面 / 编排引擎能进业务方法。`/actuator/health` `/actuator/env` `/druid` `/nacos` `/nacos/` `/xxl-job-admin` `/api/workflow/search` `/graphql` `/heapdump` `/jolokia`、Fastjson/Jackson 反序列化指纹。**看到未授权业务体就记 finding**。禁止执行系统命令、禁止 webshell、禁止反弹。利用思路写在报告里，不要真跑 `id`。
2. **SSRF（第二优先，且要能报高危）**：HTTP(S) 打到自己的外网回连或 FLAG，有响应体对照。**不报简单 DNS 日志型 SSRF**（平台不收）。不打 `127.0.0.1` / RFC1918 / `169.254.169.254` / metadata（红线 2）。不 `gopher`/`dict`/`file`。电商无回显 SSRF 取决于 PSM 是否属电商，以审核为准。
3. 未授权可读进了管理方法、可导致 RCE 的反序列化/JNDI **入口**（不加载恶意类、不打 LDAP exploit）。

## 本场允许的证明（仍要在收取范围内）

- 未授权可读：GET/HEAD 打到业务体。管理面优先。
- 越权：换 id，真实数据 ≤5 组。不测电商子账号越权。低危越权可记线索，不作为本场主目标。
- 注入：布尔 / 报错 / 一次短 SLEEP≤5s。不 INSERT/UPDATE/DELETE，不 dump。能走到 RCE/文件读再升级。
- XSS：反射 / DOM 对照。不用违法素材。不做 Self-XSS。低危 XSS 不当本场主目标。
- SSRF：只打自己的外网回连 / 平台 FLAG。不打 `127.0.0.1`、RFC1918、`169.254.169.254`、metadata。不报简单 DNS 日志型 SSRF。
- 管理面：看到未授权进了业务方法就记 finding。不执行系统命令。

## 报告（ByteSRC《AI生成漏洞报告提交规范》）

来源：ByteSRC 公众号公告（与 30+ SRC 联署）。AI 辅助挖掘**鼓励**，提交前必须**人工验证**。

报告必须有：漏洞危害说明、详细复现步骤、完整 PoC 思路、关键步骤及结果截图。用了工具要写工具名。标题含题目、影响域名、类型。

- 直接由 AI 生成、未经人工复现、或没有有效验证截图：**直接驳回，且不给驳回原因**。
- 累计超过 **3** 份未人工验证的 AI 报告：提醒。
- 累计超过 **5** 份：平台有权拉黑账号。

Lode 黑板上的 finding 一律 `verified=false`，提交前操作员人工复现。未经人工复现的 AI 报告不要丢上平台。
