# 签名预言机

## 形状

客户端把**完整待签名串**（canonical string / string-to-sign）交给自家服务端，服务端用
生产密钥 HMAC 之后把签名**返回给调用者**。

这本身不必然有问题 —— App 拿不到密钥，让服务端代签是常见设计。问题出在服务端
**没有约束这个串**：

| 该约束 | 漏了会怎样 |
|---|---|
| 调用者身份（登录态 / token / 设备证明） | 匿名即可签发 |
| HTTP 方法 | 只该签 PUT 上传，却给 GET / DELETE / HEAD 也签 |
| bucket | 能签别的桶 |
| 对象键前缀 | 能签任意键，包括他人的对象 |
| 操作类型 | 能签 ListObjects，直接列桶 |

缺任何一条，攻击者就拿到一个**签名预言机**：自行构造串 → 换一份有效签名 → 对生产存储
做那个操作。

## 怎么找到它

- 客户端出现 `CustomSignerCredentialProvider` / `getSignature` / `common/oss/signature`
  这类名字，或请求体里有 `content` / `canonicalString` / `stringToSign` 字段。
- 请求体里**带换行符**（`GET\n\n\n<date>\n/bucket/`）—— 正常业务参数不长这样。
- 云厂商的 V1/V4 规范串格式可以直接认出来。

## 怎么证它（这套证据纪律值得照抄）

| 步骤 | 正证 | 负控 |
|---|---|---|
| 列桶 | 签名 GET → 200 `ListBucketResult` | 无签名 → 403 AccessDenied |
| 读真实对象 | 签名 Range GET → **206 + `Content-Range`** | 无签名 Range → 403 |
| 写 | 只写**自己随机生成的键** → PUT 200 | —— |
| 读回 | GET 200，正文哈希一致 | —— |
| 删 | 删**自己的测试对象** → DELETE 204 | 之后 HEAD → 404，证明真删掉了 |

读真实对象时用 `Range: bytes=0-31` **只取 32 字节**并给哈希 —— 证明能读到内容，又不搬运
数据。这是"证明影响、不扩大影响"的标准做法，可以直接用。

另有一个好习惯：列出对象元数据时用 `max-keys=1` 或 10，**有界**，不做全量枚举。

## 影响边界怎么写

- 说清是**读到了真实字节**（206 + Content-Range + 哈希），不是"接口返回了签名"。
- 说清写入/删除只动**自己建的随机对象**，未覆盖任何既有对象。
- 桶名/键名脱敏；活的签名不落报告（会过期，但也不该留）。

## 修复要点

1. 客户端只提交**业务元数据**（文件大小/类型），不允许提交 bucket / method / resource /
   ACL / 完整待签串。
2. 服务端**自己生成**对象键，返回只绑定 `Method=PUT + 固定桶 + 精确随机键 + 固定
   Content-Type + 长度上限 + 1–5 分钟过期` 的**单对象**预签名 URL。
3. 上传身份 IAM 只留 `PutObject` 到单一前缀，**显式拒绝** ListBucket / GetObject /
   DeleteObject / HeadObject / PutObjectAcl / 跨桶。崩溃分析后端用**另一个**身份读。
4. 对"匿名签名 / 非 PUT 方法 / 桶根资源 / 跨日期前缀"建告警。
