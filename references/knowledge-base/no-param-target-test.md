# 目标没有参数怎么办

"整站找不到参数"通常不是真没有，而是你还没拿到**登录态之后**的那部分。

## 顺序

1. **每个入驻/入口都登一遍**，再收集 JS、跑 JS。很多接口只在登录后才被引用。
2. 页面"不加载"可能只是**前置资料没填完** —— 把表单填完整，接口才出现。别当成没接口。
3. 拿到路由但不知道要什么参数时，**让模型从路由名反推**。

## 把 JS 收全（漏一个 chunk 就没参数）

登进一个入口之后，别只看首页那一个包 —— 现在的前端是**主包 + 一堆数字编号的 chunk**：

```
/static/js/main.0255e11b.chunk.js
/static/js/92.d3a8274d.chunk.js     ← 编号连号，说明还有 1、2、3… 没被加载
```

做法：先把流量里已加载的 js 列出来，看出"编号连号"就**照着编号把没加载的补齐**再批量跑。
用 HAE 的 Linkfinder 规则跑：先跑 HTML 页拿 js 列表（**不同 HTML 页面要分别跑**），
再拿这份列表跑 js；js 里还会再引用 js，**要分批多轮跑完**。

跑 js 时把 `.` 换成 `_`（intruder 里作为 payload 占位），并且**不要勾去重** —— 勾了数量对不上。

最后在 logger 里搜目标接口名（比如 `xxxClientApi.export_绑定接口`）定位调用点，
那里就是完整的参数列表（`order_by` / `order_direct` / `pageSize` / `status` 一连串）。

找不到调用处别急着判"没这个接口"：**大概率是懒加载**，去触发对应功能点它才加载。

## 路由名 → 参数（这一步最省时间）

把路由路径丢给模型，问"这个接口大概做什么、可能有哪些参数、还可能是哪些功能"。可以直接
用这个提示词：

> 请你分析以下为一个 API 查询功能提供的参数列表，并帮我完成以下任务：
> 1. **筛选与整合**：筛出所有与业务查询相关的参数，包括功能重复或相似的
> 2. **生成请求字符串**：拼成一个标准 URL query string
> 3. **赋值规则**：通用参数（分页、状态）用常见默认值；动态/敏感参数（ID、token、签名）
>    用清晰占位符（如 `YOUR_APP_KEY`）
> 4. **格式化输出**：先给完整 query string，再按功能类别（身份/状态/分页）逐条解释

反推出来的参数表直接扔进代理发包。**报错也不亏** —— 报错本身就是"哪些参数名不对"的信息。

## 参数名也要 fuzz（关键一步）

参数名从来不唯一：`page` / `pageSize` / `page_size` / `pageNum` 都有人写。
做法是**在已捕获的流量里搜相关词**，把同义写法都列出来，再在目标上 fuzz 组合。

> 这里有个反直觉点：`pageSize` 这类"另一个人的写法"往往就藏在你自己的历史流量里 ——
> 同一个厂商的不同接口会各写一套。先搜流量，再花请求。

## 注入点优先看命名规约

找不到注入点时，`order by` / `order_by` / `orderBy` 是高频命中处 —— 排序字段通常**直接拼进
SQL**，而且没人知道它到底怎么写，所以名字得试。实在不行就上 SQLi 参数字典 fuzz。

## 为什么这套有效

它不依赖"我猜对了参数"，而依赖**三个便宜的枚举**：

1. 枚举入口（把每个入口登录一遍，收全 JS）
2. 枚举参数名（在流量里搜同义写法）
3. 枚举注入参数名（字典）

每个枚举都便宜，合起来覆盖面很大。反过来，"盯着一个页面找参数"是最贵的做法。
