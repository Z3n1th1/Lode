# 可转发凭据不绑定使用者

签发接口给出一个**凭据**（ticket / 一次性 URL / 32 位 hex / 签名串），校验方只核对
"这东西确实是我签的"，**不核对"现在拿它的这个人是不是当初那个人"**。于是任何拿到票的人都能顶替签发者。

和 `anon-id-chain-test.md` 的区别：那边漏的是 **id**（详情接口不校验归属），这边漏的是
**凭据本身** —— 凭据是真的、有效的、没过期，只是换了个使用者。

## 找

- 签发口长成 `.../ticket`、`.../token`、`.../signed-url`、`.../ws/ticket`
- **签发物挂在 URL query 上**而不是 Cookie/Header 上 —— 这就是"可复制、可转发"的信号
  （能进日志、能贴给同事，也就能贴给攻击者）
- 用它的那一端往往是个长连接/网关（WebSocket、SSE），因为这类连接不容易塞自定义头

## 打

1. 账号 A 正常走一遍，拿到 A 的凭据（示例：`GET /open-apis/user/ws/ticket` → `data.ticket`）。
2. 账号 B 用自己的登录态（Cookie/B 的票）去连接/请求，**只把凭据换成 A 的那张**。
3. 读 A 的对象（会话列表、消息正文、私有文件）。

## 判据（缺一条就不能写成跨用户）

| 要素 | 要求 |
|---|---|
| 安全不变量 | 一句话写清"谁只应看到自己的什么" |
| H0 基线 | 自己连自己时能看到什么（条数、字段、正文） |
| 单变量对照 | 只改了凭据这一个变量 |
| 对象字节 | 证据落在**受保护对象的字节**上 —— A 的列表条数与 B 自己的不同、正文里出现 A 的 canary |
| 负控 | 不带凭据 401；乱填凭据 401；换回 B 自己的凭据必须只读到 B 的 |

**光有"连接成功""升到了 operator"不算** —— 那只是进了门。必须读出别人的内容。

## 两个必须写对的地方

- **别把"需要自己的登录态"写成"完全匿名"。** 这类洞通常是"已登录的 B 能读 A 的"，不是
  "未登录可读"。定级时这条差别很大，写错会被打回。
- 签发物**会失效**：签完立刻用；它常被设计成一次性或短 TTL，报告里说明可重放性。

## 证据卫生

- canary 用自定义标记串，便于在正文里定位；不落盘原文、不外发。
- 签发物是活的凭据，**不进报告正文**（贴结构不贴值）。
- 只证明"读到了"，不做写入/接管延伸 —— 那属于另一条链，要单独证。
