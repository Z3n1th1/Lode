# 客户端信任服务端返回的授权结论

授权判定如果**发生在客户端的渲染/判断里**，那服务端只是在"告知"，不是在"把关"。
这类洞改一个响应字段就过，成本极低，但**必须证到内容**，否则只是界面骗自己。

## 形态一：校验接口的响应体就是开关

入口是一句"你先认证一下"的校验请求，响应里带着结论字段：

```
POST /.../RoomAction/GeneralValidate   → {"result":1,"data":{"code":51001,"auth_status":0,...}}
POST /.../mini/whiteList/check?...     → 210
```

把结论字段改成通过（`code` → 成功码、`auth_status` → 0/1、`status` → 1，或 HTTP 210 → 200、
`msg` → "成功"），后续请求放行。

**两个包都要改**是常态 —— 前端会在不同时机问两次，只改一个仍然进不去。

## 形态二：凭据由另一个响应下发

不用爆破密码，往往是"另一个接口把它送下来了"：

1. 抓"刚点击这个加密会议"的响应 → 里面有 `password`（密文）
2. 抓提交密码的请求 `.../GeneralValidate` → 把 password 字段换成第 1 步拿到的值
3. 通过

同一个"提密"链路上，明文提取码也可能直接出现在落地 HTML 或 `syncData` 里（见 `file-upload-test.md`
「密码分享回包带明文提取码」）—— 能抄就别爆破。

## 判据：证内容，不证界面

改包之后**必须真的拿到受保护内容**：

- 受保护的媒体流地址（`.m3u8` + 容器头 + 体积）
- 受保护的实时数据流（WebSocket / 长连接在持续交互）
- 别人会话/文档的正文

只证明"界面进去了""按钮能点了"**不算** —— 那可能只是前端没拦，后端照样空响应。

## 纪律

- 只改**判定字段**（状态码、msg、auth 标志），不动业务数据。
- 报告里 before/after 两个包都要给，读者要能一眼看出只改了哪一个字段。
- 受保护内容取最小证明（容器头 + 体积 / 一条正文），不下全量、不外传。
- 直播/会议这类时效性内容，取不到当时的画面就如实说明，用**数据流特征**（持续交互、实时
  分片）作为"确实拿到了"的旁证。
