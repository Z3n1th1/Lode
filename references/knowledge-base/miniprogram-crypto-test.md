# 小程序加解密与「密文不是授权」

小程序把请求/响应整体加密是常态。**加密不改变漏洞，只改变你能不能看见它** —— 所以这步不是终点，
是让后面所有测试回到明文的前提。

## 一、拿到包

- everything 搜 `.wxapkg`，找小程序缓存目录（先看有没有加密）
- 工具链：`wxapkg`（scan / 解包）、`AutoDecompileApplet`、`wedecode`
- **坑**：缓存目录常多一层（比如先一个 `【66】` 目录才到 `.wxapkg`）。只盯一层的工具会"能监测到但解不开"，
  换个工具或自己往里走一层

## 二、定位加解密

反编译出来的 JS 里全局搜 `encrypt` / `decrypt` / `crypto` / `cbc` / `aes`，
看 mode、padding、iv 各自从哪来。

**最常见的陷阱是两层密钥**：`aesDecrypt(e)` 里的 `key`/`iv` 都是 `g()` 的返回值，
而 `g()` 自己又是"用硬编码的 KEY1/IV1 解一段硬编码密文"得来的。

```js
function g() { return Decrypt("505288B2...5DD2C2FE522E31"); }   // 第二层
var t = r.enc.Utf8.parse(g()), n = r.enc.Utf8.parse(g());        // 真 key/iv
return r.AES.decrypt(e, t, { iv: n, mode: CBC, padding: Pkcs7 });
```

所以直接拿 KEY1 当 key 会"密钥错误"。**照着 `g()` 再解一次**才拿到真 key。
常见附带特征：key 和 iv 相同；密文是 base64 或 hex 两层编码。

## 三、让它自动跑

密钥一旦拿到，别手工解：

- Burp 插件 `Galaxy`（RPC 到本地服务）、`CloudX`、`autoDecoder` 任选
- 有的需要在选项里勾"双配置文件模式"才会出现解密按钮
- 配好之后 **Proxy → HTTP history 里所有包体自动明文**，回到正常测试节奏

验证码类重复劳动也能挂在同一条链上（本地 RPC 解析后自动填），注意验证码池没维护会大量失效。

## 四、关键判据：密文不是访问控制

解密之后如果响应里装着**本不该给你的东西**，那就是信息泄露，跟加密无关。

真实形态：小程序响应里一个 `pdfurl` 字段是密文，解密后是**内部研究报告的 OSS 直链**。

判"该不该给你"看**正常路径**：

- 小程序上没有这个下载入口，不是正常业务功能
- 点主页的"研究报告"会跳登录，而登录要求**内部开通**，不能随便注册
- 于是：正常路径拿不到 + 你解出来了 = 越权拿到

成立还要加一层：这批直链**每天新增**，说明不是历史遗留，是持续可取的。

## 纪律

- 只取**一条**证明（容器头 + 体积即可），不批量下载他人文档。
- 解密脚本里的 key/iv 和直链不进报告正文，贴结构不贴值。
- 目标站是敏感站点时点到为止，一位字符级证明足够。
