# 组件

## 原则

- **容器 vs 展示**：页面组件管数据与动作，子组件只管渲染与事件。
- **契约显式**：`props` / `emits` 用 TS 类型写清；不通过 store 偷传 props。
- **大小可控**：单组件超过 ~250 行就拆；历史教训是 611 行的 `ConsoleChat.vue`。
- **无隐式全局**：不在组件顶层副作用里发起请求；放到 store 动作或 composable。

## 统一渲染器的卡片类型

聊天流用"一种渲染器 + 多种卡片"结构，新增类型时：

1. 在 `components/chat/` 下加卡片组件（如 `FindingCard.vue`、`SubtaskCard.vue`）。
2. 在渲染器里按事件的 `kind` 分派；未知 kind 降级为纯文本，**不能崩**。
3. 卡片只接收一份事件对象，自己不做请求。
4. 补一个该卡片的最小渲染测试。

## 流式内容

- 滚动跟随要可关（用户上滑后不再强制拉到底）。
- 流未结束时展示进行态；结束时收尾（避免"永远转圈"）。
- 长列表用窗口化，不要无脑渲染全部历史。

## 反例（不要做）

- 组件里直接 `fetch` 而不走 `api.ts`。
- 把展示逻辑写进 `store.ts`。
- 为一次性的需求造通用抽象层。
