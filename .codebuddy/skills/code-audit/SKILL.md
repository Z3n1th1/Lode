# 代码审计 — 调度器

这是**白盒**审计，不是把危险函数清单念一遍。你要证明的是
**可达性**：外部输入能不能走到危险操作，中间有没有被有效拦截。

## 0. 铁律

1. **可达才算**：没有从 source 到 sink 的完整路径，就只是"潜在风险"，不是发现。
2. **证据链**：每条发现给出 `文件:行 → 传播路径 → 触发条件 → 影响`，能被人独立复核。
3. **先广后深**：先扫入口与危险点建立候选，再对高价值候选做完整污点追踪；不做无目标的全量逐行读。
4. **不猜框架**：不确定行为就去读依赖源码/文档，不凭印象下结论。
5. **不改造目标**：审计只读；不为了"验证"去改动目标代码或数据。

## 1. 工作循环

- **建面**：找 source（入口）与 sink（危险操作）两个集合 → 模块 `sink-scan.md`。
- **连线**：从 source 追数据流到 sink → 模块 `taint.md`。
- **排雷**：途中识别 sanitizer / 校验 / 类型约束，判断能否绕过。
- **翻底**：配置与密钥泄露单列 → 模块 `secrets.md`。
- **专类**：反序列化、模板、表达式这类整条链单独看 → 模块 `deserialization.md`。

## 2. 模块索引（按需加载）

| 阶段 | 模块 |
|---|---|
| 危险函数 / sink 枚举 | `modules/sink-scan.md` |
| 污点追踪（source→sink） | `modules/taint.md` |
| 硬编码密钥与配置泄露 | `modules/secrets.md` |
| 反序列化 / 对象注入 | `modules/deserialization.md` |

## 3. 输出要求

- 按严重级别排序；每条含：位置、数据流、触发条件、影响、修复建议、置信度。
- 明确区分**已证明可达**与**疑似**（缺哪一段证据要说清）。
- 高危结论必须能回答："拦截点在哪里，为什么它拦不住？"
