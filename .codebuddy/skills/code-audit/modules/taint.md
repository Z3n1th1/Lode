# 污点追踪

## Source（外部可控）

- HTTP：query/body/path/header/cookie；文件上传名与内容。
- 消息/队列：消费到的事件体、webhook payload。
- 数据层：数据库里已被别人写入的字段（二次注入源）。
- 环境：命令行参数、环境变量、配置文件（可控性需说明）。
- 第三方响应：被审计系统去调用别人接口拿到的数据。

## 传播

沿赋值、拼接、格式化、容器（list/dict/对象属性）、参数传递、闭包一路跟到底。
注意"跨边界"的点：工具函数、装饰器、中间件、序列化后再反序列化。

## Sanitizer（拦截点）

判断拦截是否**真的有效**，而不是"看起来做了校验"：

| 校验 | 常见失效 |
|---|---|
| 黑名单过滤 | 大小写、编码、双重写、注释符、Unicode 归一化绕过 |
| 正则白名单 | 未锚定 `^$`、`.` 未转义、多行标志 |
| 类型转换 | `int()` 强转有效但 `float`/`Decimal` 可能仍可控 |
| 转义 | HTML 转义防 XSS 但不防 SQL/命令；上下文错误 |
| 路径校验 | 只查前缀字符串，未 `realpath` 归一化（`../`） |
| 框架 ORM | 参数化安全，但 `raw`/`extra`/`order by` 仍可注入 |

## 结论模板

```
SOURCE  <入口>            文件:行
  ↓ <传播说明>
SANITIZER <校验>          文件:行   → 判定：有效 / 可绕过（原因）
  ↓
SINK    <危险操作>        文件:行
影响：<能做什么>
```
