# 组合利用链

单个"低危"弱点常常可以串成"高危"。目标是把弱点连成**有依赖顺序**的链。

## 思路
1. 列出所有弱点：信息泄露、越权、注入、SSRF、配置错误……
2. 找出"解锁关系"：谁能拿到下一步需要的东西（token、内部地址、文件）。
3. 按依赖排序，只验证到能证明影响为止。
4. 记录为 DAG：`A unlocks B`，便于复核与还原。

## 常见链
- 信息泄露（源码/配置）→ 发现隐藏端点 → 越权 → 数据泄露。
- SSRF → 内网服务 → 云元数据（只证明可访问）。
- 任意文件读 → 读配置 → 拿到签名密钥 → 伪造 token。

## 纪律
- **不做破坏性验证**：证明影响存在即可，不实际导出数据、不横向移动。
- 链条每一步都要有独立证据；不能靠"推测应该可行"。
- 高价值链必须走人工复核门。
