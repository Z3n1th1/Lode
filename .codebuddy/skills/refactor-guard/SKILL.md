# 重构守护

重构的目标是**行为不变、结构变好**。这个 pack 是它的护栏，不是可选项。

## 0. 五条规则

1. **先有安全网**：动结构前，先给将被改动的行为加特征化测试并**单独提交**。
   测试没绿之前不开始改结构。
2. **冻结契约再动手**：路由集合、公开函数签名、导出符号、事件类型都是契约。
   要改就**显式**改契约测试，并在提交信息里说明原因——不允许"测试红了顺手改"。
3. **删除前查引用图**：`grep` 全仓确认唯一消费者。多消费者先逐个迁移，最后删；
   有测试覆盖的模块删前确认测试的用意（验证行为 → 保留；验证已删实现 → 一并删）。
4. **小步可回滚**：一步一个提交，破坏性阶段前打 tag。宁可多提交，不要一个大 diff。
5. **每步跑测试**：Python `pytest -q` + 前端 `vitest run` 必须绿才继续。绿了再走下一步。

## 1. 顺序（照做）

```
打 tag / 加特征化测试
  → 逐个小步提交（每步测试绿）
  → 改契约测试（显式、单独提交、说明理由）
  → 删除已无消费者的代码
  → 打 tag
```

## 2. 不夹带

- 重构不掺功能变更；功能变更不掺重构。混在一起，出问题无法二分定位。
- 不留 `# removed`、`_unused` 之类的兼容残骸：确认无用就删干净。
- 不加"将来可能有用"的开关、抽象层、转发函数。

## 3. 判断"能不能删"

| 情况 | 动作 |
|---|---|
| 全仓无引用，无测试 | 直接删 |
| 全仓无引用，但其测试在验证行为 | 确认行为已被别处覆盖 → 否则**不要删** |
| 仍被外部契约（文档/脚本/下游）引用 | 先更新引用方，再删 |
| 拿不准 | 先留着，记进死路清单并说明原因 |

## 4. 完成标准

- 行为不变（测试证明），结构更简单（行数/文件数下降，引用关系更清晰）。
- 提交历史能让人一步步看懂你怎么走的。
- 没有留下"以防万一"的兼容层。
